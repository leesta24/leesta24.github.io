一句话摘要

Comma 的本地照片搜索搭建指南：iPhone 照片经 iCloud 同步到 Mac 后，用本地模型做 OCR + 双向量（Chinese-CLIP 与 Qwen3-VL-Embedding）建索引，agent 通过 lpa 命令搜索——agent 只拿到照片 ID、日期、识别文本与候选缩略图联系表，用户选定后才把原图送进对话；照片本体不离开本地，索引永不外发。

主要要点

  • 隐私架构: agent 不需要照片副本；重活（OCR、向量化）由本地模型做；agent 只拿到搜索结果（ID、日期、识别文本、需要挑选时的一张缩略图联系表），最终选定的照片才进对话。注意点：若 Comma 用云端模型，搜索结果与被查看的图片仍会发给模型厂商；"本地"指 OCR、向量与索引在导出之后全本地；Comma 开源、可自托管。
  • 搭建三步: iCloud Photos 同步到 Mac 并每日导出到文件夹 → 本地模型处理（每图 OCR + Chinese-CLIP + Qwen3-VL-Embedding 向量化）→ 存入本地数据库，一个命令 lpa 搜索。iPhone 端不做任何改动。
  • 搜索结果的证据分级: Text match（全部词都在图片文字里）、Possible（看起来像，容易混淆）、Low confidence（没有更好时才展示）；--prefer text 优先文字匹配（证件、卡片、截图），--prefer picture 优先形似图片（猫、海滩）；几分钟内拍的近重复照片合并为一条结果。
  • 不确定时不猜: 候选不确定时 agent 把缩略图排成一张最多 9 格的编号联系表请用户选（"1 and 2"），选定后才发送。
  • 双模型校准（约 5 万张库实测）: 单用 Qwen3-VL-Embedding 时人工选中的正确答案排名低于单用 Chinese-CLIP；双排名合并后每项至少不差于任一单模型；"Possible"要求双模型相似度同时过线后，一次查询的候选从 4,970 降到 4；代价是搜索从约 3 秒变 3.5–6 秒。
  • 硬件与升级路径: 示例在 16 GB MacBook Air 上跑 Qwen3-VL-Embedding-2B；可换 8B 向量模型（需全部重算向量）；可加 Qwen3-VL-4B/8B-Instruct 生成每图一句话描述与标签存入文本索引（24 GB MBP 上 8B 用 8-bit 量化；标签只作粗筛，不保证正确）。
  • 语言处理: Chinese-CLIP 主要在中文图文上训练，英文查询不可靠；OCR 中英文都读，Qwen3-VL-Embedding 多语言——做法是把中英文表述放进同一次搜索（可写进 Skill）；英文为主的库可换回原始 CLIP（同样需重算向量）。
  • 找人: 直接用 Apple Photos 已有的人脸分组，自身不做人脸识别；命名流程是 agent 分批编号请用户确认（"3 是妈妈"），未确认的分组不视为任何人；按人名搜索（提两人则只返回两人同框），可与内容、时间组合；名字未确认或重名时明说而不猜；纠错可撤销。
  • 视频搜索: 与照片分开（默认只搜照片），--source video 才搜；视频本身不进模型，每 5 秒取一帧、每视频最多 12 帧，帧按照片流程处理，帧命中即整个视频作为一条结果，lpa video 发送；局限：不搜声音、不识别视频里的人、长视频中一闪而过的画面可能漏掉。
  • LocalPhotoAgent（lpa，作者自研、将开源）: 每步每图单独记录进度，可随时停、续跑，改设置只重跑受影响步骤；工作时监控内存、温度、磁盘空间，超限暂停；命令只有 search / sheet / preview / video 四个。
  • 接 Comma: Settings > Devices 添加设备 → 在存照片的 Mac 上装 Comma Connector → 访问权限开到 Full → 写一条 Skill（先搜索、不确定时给联系表、用户选定后再发送）。
  • 信任与边界: 索引只读原件，永不移动/编辑/删除；搜索不碰外置硬盘（只有做联系表或发送时才读）；但 Full 权限意味着 agent 在这台 Mac 上也能跑 lpa 之外的命令；文字匹配只说明词被找到，不等于就是你要的照片；标记完成时仍需自己检查发来的照片。

适用场景

  • 个人 agent 的本地多模态检索参考：OCR + 双向量融合 + 证据分级的搜索设计
  • 隐私敏感资料（证件、卡片）的"索引本地、结果进对话"模式
  • 与"agent 看不到手机相册"类限制的绕过思路对照：不直连手机，改在已有同步路径（iCloud → Mac）上建索引
